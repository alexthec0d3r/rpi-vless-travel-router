# Setting Up a VLESS+Reality Server

This guide covers setting up your own xray server with VLESS+Reality. If you already have a server, skip this — the travel router works with any VLESS+Reality server.

## Requirements

- A VPS with a public IP (any cloud provider works)
- Ubuntu 22.04+ or Debian 12+
- Root access

## Quick Setup

### 1. Install xray

```bash
bash -c "$(curl -L https://github.com/XTLS/Xray-install/raw/main/install-release.sh)" @ install
```

### 2. Generate credentials

```bash
# Generate UUID
xray uuid
# Example output: a1b2c3d4-e5f6-7890-abcd-ef1234567890

# Generate Reality key pair
xray x25519
# Example output:
# Private key: YOUR_PRIVATE_KEY
# Public key:  YOUR_PUBLIC_KEY
```

Save these — you'll need the **UUID** and **public key** for `config.env`.

### 3. Generate a short ID

```bash
openssl rand -hex 8
# Example: 0a1b2c3d4e5f6a7b
```

### 4. Configure xray

Create `/usr/local/etc/xray/config.json`:

```json
{
  "inbounds": [
    {
      "listen": "0.0.0.0",
      "port": 443,
      "protocol": "vless",
      "settings": {
        "clients": [
          {
            "id": "YOUR_UUID",
            "flow": "xtls-rprx-vision"
          }
        ],
        "decryption": "none"
      },
      "streamSettings": {
        "network": "tcp",
        "security": "reality",
        "realitySettings": {
          "show": false,
          "dest": "www.google.com:443",
          "xver": 0,
          "serverNames": ["www.google.com"],
          "privateKey": "YOUR_PRIVATE_KEY",
          "shortIds": ["YOUR_SHORT_ID"]
        }
      }
    }
  ],
  "outbounds": [
    {
      "protocol": "freedom",
      "tag": "direct"
    }
  ]
}
```

Replace `YOUR_UUID`, `YOUR_PRIVATE_KEY`, and `YOUR_SHORT_ID` with values from step 2-3.

### 5. Start xray

```bash
systemctl enable xray
systemctl start xray
systemctl status xray
```

### 6. Configure your travel router

In `config.env`:

```bash
VPN_SERVER_ADDRESS="your.server.ip"
VPN_SERVER_PORT="443"
VPN_UUID="your-uuid-from-step-2"
VPN_REALITY_PUBLIC_KEY="your-public-key-from-step-2"
VPN_REALITY_SHORT_ID="your-short-id-from-step-3"
VPN_REALITY_SNI="www.google.com"
VPN_TRANSPORT="tcp"
```

## Choosing an SNI Domain

The Reality protocol mimics a TLS connection to a real website. Pick a domain that:
- Is hosted on the same cloud provider as your VPS (for realistic latency)
- Uses TLS 1.3
- Is not blocked in the target region

Common choices: `www.google.com`, `www.microsoft.com`, `www.apple.com`

## XHTTP Transport (Alternative)

For more restrictive networks, you can use XHTTP instead of TCP/Vision. This makes traffic look like regular HTTPS API calls. See the [xray documentation](https://xtls.github.io/) for XHTTP server configuration.

Set `VPN_TRANSPORT="xhttp"` and `VPN_XHTTP_PATH="/yourpath"` in `config.env`.

## Security Notes

- Keep your private key **private** — only the public key goes in `config.env`
- Use a strong UUID (generated by `xray uuid`, not a simple one)
- Consider using a firewall (ufw) on the server to only expose the xray port
- Regularly update xray: `bash -c "$(curl -L https://github.com/XTLS/Xray-install/raw/main/install-release.sh)" @ install`
